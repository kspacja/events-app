# Etap 1.5 — Obserwowalność

**Cel:** każdy błąd i każde wolne żądanie da się prześledzić od portalu przez API po bazę.

## Decyzje (podjęte)

- Zakres: to, co już istnieje — `apps/portal` i `apps/api`. Worker, outbox i opóźnienie outboxa dochodzą z etapem 5 (worker jeszcze nie istnieje).
- OpenTelemetry bez wybranego backendu (ADR-0011): ślady, metryki i logi wychodzą przez OTLP tylko, gdy ustawiono `OTEL_EXPORTER_OTLP_ENDPOINT`; bez niego nic nie jest wysyłane. Backend wybieramy później.
- Portal: `@opentelemetry/sdk-node` z instrumentacją undici w `instrumentation.ts` (ręczna konfiguracja, którą Next wspiera); kontekst śladu (`traceparent`) idzie do API w `fetch`. Nie `@vercel/otel`: wersja 2.x wymaga OpenTelemetry <0.300, a API używa 0.300 — w repo jest jedna linia OpenTelemetry. API (Hono): `@opentelemetry/sdk-node` z instrumentacją HTTP i `pg`. Jeden ciągły ślad: strona → API → zapytanie do bazy.
- Próbkowanie: 50% śladów, zależnie od rodzica (API idzie za decyzją portalu). Na początku ruch to testowi użytkownicy.
- Logger: pino z wyjściem JSON zamiast `lib/logger.ts` i `console.*` w API; każdy wpis ma `trace_id` i `span_id` aktywnego śladu; pola z danymi osobowymi są maskowane.
- Błąd 500 w API zwraca identyfikator śladu, żeby zgłoszenie dało się odnaleźć w logach; `app.onError` obejmuje każdy nieobsłużony błąd API (log, Sentry, 500 z `traceId`).
- Raportowanie błędów: Sentry (`@sentry/nextjs` w portalu — serwer i przeglądarka, `@sentry/node` w API), tylko błędy, bez własnych śladów Sentry (ślady są w OpenTelemetry). Włącza się dopiero z `SENTRY_DSN` / `NEXT_PUBLIC_SENTRY_DSN`; na razie bez DSN, więc nic nie jest wysyłane.
- RODO: w telemetrii i raportach błędów bez e-maili, adresów IP i identyfikatorów Gościa; identyfikator konta (od etapu 2) najwyżej jako skrót. Atrybuty z adresem IP klienta (`client.address`, `network.peer.address`) są usuwane ze śladów API.

## Kroki

A. API: OpenTelemetry, logger pino, identyfikator śladu w odpowiedzi 500.
B. Portal: `@opentelemetry/sdk-node` z instrumentacją undici, przekazywanie kontekstu do API, logger pino na serwerze.
C. Sentry w portalu i API, wyłączone bez DSN.

## Kryterium ukończenia

Wejście na miesiąc `/dla-szkol` z lokalnym API daje jeden ślad portal → API → baza (sprawdzone eksporterem do konsoli albo lokalnym kolektorem); błąd `OccurrenceSourceError` trafia do logów z przyczyną i `trace_id`, a z ustawionym DSN — do Sentry; w telemetrii nie ma danych osobowych; bramki zielone.
